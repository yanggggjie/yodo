# yodo 图标设计

| 文件 | 作用 |
|---|---|
| [`icon.py`](icon.py) | **源文件**：所有参数都在里面，只用 python3 标准库 |
| [`icon.svg`](icon.svg) | 由 `icon.py` 生成并提交，不要手改 |
| [`make-icons.sh`](make-icons.sh) | 一条命令：先生成 SVG，再出 `skills/yodo/src/chrome-extension/icons/` 下 16、32、48、128 四个 PNG（需要 `rsvg-convert`） |

`sh brand/make-icons.sh` 生成的图标已验证与 2026-10-16 选定的版本逐像素一致（三个尺寸差异均为 0）。

## 一句话

**整个图标面就是一个 y。** 不是在方块里放一个 y 图案，而是整个方块被两条白色曲线画成 y，并分成三块渐变色，每一块是 y 的一部分：上方是两臂之间，左侧是左臂以下，右下是尾巴一侧。

## 设计原则

1. **整体即符号。** 图案占满整个图标面，没有"底板 + 图案"的分层。曲线从画布外伸进来、从画布外伸出去（坐标超出 0 到 128），线是出血的，所以看起来是整面被切开，而不是一个图形摆在中间。
2. **用名字做形状，而不是借通用符号。** 圆点、光标、涟漪、放大镜这类符号太常见，让人觉得在哪里见过。y 来自产品名，只属于 yodo。
3. **一个形状只表达一件事。** 两条线、三块色，没有第三种元素：没有点、没有箭头、没有文字。
4. **最小尺寸优先。** 工具栏上最常见的是 16 像素。先在 16 像素下判断，再看 128 像素好不好看；16 像素下认不出的，128 像素再漂亮也不要。
5. **对比先于装饰。** 白色的 y 必须在三块颜色上都清楚。任何一块颜色太浅（比如淡桃色）都会削弱白线，宁可深一点。
6. **颜色用来建立身份。** 扩展图标大多是蓝、灰或单色。暖色的橙、玫红加上冷色的靛紫，在工具栏里一眼能认出来。

## 构成与规格

画布 `128 × 128`，圆角矩形 `rx = 30`（约 23%），四角透明。

| 部分 | 几何 |
|---|---|
| 相接点 V | `(70, 84)`，在画布约 55% 宽、66% 高处。位置偏下，使短臂较长、尾巴在下方，比例像小写 y |
| 短臂 | 三次贝塞尔，`(-12,-12)` → V，终点处方向很陡（最后一段控制点 `(56,36)` 到 V），像手写时的一笔汇入，而不是硬接 |
| 长斜线 | 从右上 `(140,-14)` 经 V，尾巴向左弯出左边缘 `(-12,122)`。V 前后的切线方向基本一致，所以是一条连续的曲线 |
| 线宽 | `22`，约占画布 17% |
| 端点 | 圆头（`stroke-linecap: round`），拐角圆角（`stroke-linejoin: round`） |

### 线宽的依据

白线宽度决定小尺寸下 y 能不能认出来。线宽按比例缩小：画布上宽 6 到 9 的线，在 16 像素下只有约 0.75 到 1.1 像素，太细；评审时看过宽 9 的版本，被要求加粗。最终取宽 22，在 16 像素下垂直于线的宽度约 2.75 像素。规则：**白线不少于画布的 14%，使 16 像素下至少 2 像素。**

按 128 像素图标统计，白线约占不透明面积的 33%，有色的三块合计约 67%：白线本身就是主角。

### 曲线的依据

"自然"来自三点：

- 所有线段都是三次贝塞尔，不用折线，也不用圆弧拼接。
- 在相接点 V，长斜线前后的切线方向一致（进入 V 的方向约 `(-26, 36)`，离开 V 的控制点方向约 `(-12, 20)`）。
- 短臂以较陡的角度汇入，像一笔写成的分支。

## 怎么做出来的

按顺序，每一步都对应 `icon.py` 里的一组常量：

1. **定画布。** `128 × 128`，圆角 `rx = 30`，用 `clipPath` 裁切，所有内容出血到圆角之外。
2. **定相接点 V `(70, 84)`。** 它是短臂和长斜线相接的地方。放在 55% 宽、66% 高：太高，尾巴没有空间；太低，短臂会显得像一整条线。
3. **画长斜线。** 两段三次贝塞尔：第一段 `S(140,-14)` 到 `V(70,84)`，控制点 `C1(118,14)`、`C2(96,48)`；第二段 `V` 到 `E(-12,122)`，控制点 `C3(58,104)`、`C4(46,124)`。`C2→V` 方向 `(-26,36)`，`V→C3` 方向 `(-12,20)`，近似同向，所以过 V 时切线连续，是一条流畅的线；到 E 时向左弯出左边缘，形成小写 y 的钩。
4. **画短臂。** 一段三次贝塞尔：`A(-12,-12)` 到 `V`，控制点 `C5(22,2)`、`C6(56,36)`。`C6→V` 方向 `(14,48)`，很陡，像手写时从侧面一笔汇入。
5. **用同样的曲线切出三块区域。** 这是关键：区域的边界就是那两条白线本身，所以线和色块永远对得上。
   - 上方区域：整个画布的底色。
   - 左侧区域：沿短臂 `A→V`，再沿长斜线下半 `V→E`，沿画布外缘回到 `A`，闭合。
   - 右下区域：从 `S` 向右越过画布到右下外角，沿底边到左下外角，再沿左边外缘到 `E`，然后沿长斜线**反向**回到 `V`、再回到 `S`。反向时每段的两个控制点顺序对调（`C4,C3` 和 `C2,C1`）。
6. **上色。** 三块各一条两色渐变，渐变坐标写在画布坐标系里（`userSpaceOnUse`），所以不随区域形状变化。
7. **盖白线。** 最后画两条白线，宽 22，圆头，拐角圆角。白线盖住色块的边界，也盖住色块拼接处的缝。

绘制顺序固定为：底色 → 左侧 → 右下 → 短臂线 → 长斜线。

## 配色

| 区域 | 渐变 | 方向 |
|---|---|---|
| 上方（两臂之间） | `#FF8A5B` → `#FF3D6E`（橙到玫红） | 左上到右下 |
| 左侧（短臂以下） | `#24166B` → `#6C3BE0`（靛紫到亮紫） | 从上到下 |
| 右下（尾巴一侧） | `#FFC857` → `#FF8A3D`（金黄到橙） | 从右上到左下 |

- **冷暖对比**：左侧是冷色，另两块是暖色。按 128 像素图标统计，冷色约占整个图标面的 26%，暖色约占 41%（其余是白线），所以暖色是主调，冷色是对照，三块的边界不只靠白线区分。
- **明度对比**：左侧最深，右下最亮，上方居中。在 16 像素的评审图里，白线在三块上都清楚。
- **避免过浅**：评审过淡桃色的上方（金色黄昏方案），16 像素下上半部分的白线对比度明显下降，因此放弃。

## 小尺寸检查方法

每次改动后，把 `16、48、128` 像素各渲染一次，并把 16 像素用最近邻放大到 64 像素，分别放在白底（浅色工具栏）和 `#202124`（深色工具栏）上看：

1. 16 像素下还能认出是 y 吗？
2. 白线至少有 2 像素宽吗？
3. 三块颜色在两种背景下还能分开吗？
4. 圆角处有没有出现明显的杂边？

## 被否决的方案

| 方案 | 否决原因 |
|---|---|
| 圆点加光标（"一次点击"） | 鼠标光标图标太常见，16 像素下光标太小，整体偏杂 |
| 圆点加一圈涟漪 | 像单选框、录制键或目标，不独特 |
| 圆点加一道斜线 | 看起来像百分号 `%`，会误导 |
| 圆点加一段弧线 | 像 RSS 或 WiFi 图标 |
| 数字 1 加圆点 | 表达了"只做一次"，但不是产品名，也没有个性 |
| 沿笔画排一串重叠的圆 | 128 像素好看，16 像素糊成一团 |
| 四段分开的粗胶囊拼成 y | 段与段之间有缺口，看起来像断开的 y |
| 方块内对称的 Y 形三分 | 像三叉或和平标志，不像小写 y |
| 蓝绿、青柠配色 | 蓝绿在工具类扩展里太常见；青柠偏"环保"类产品 |

## 如何修改

1. 改 `brand/icon.py` 里的常量（不要手改 `icon.svg`，它会被覆盖）。
2. 运行 `sh brand/make-icons.sh`，重新生成 `icon.svg` 和 `skills/yodo/src/chrome-extension/icons/` 下的四个 PNG。
3. 按上面的方法检查小尺寸。
4. 在 `chrome://extensions` 里刷新 yodo 扩展才能看到新图标。扩展的版本哈希只算 `background.js` 和 `manifest.json`，只改图标不会触发 `doctor` 的刷新提示。
