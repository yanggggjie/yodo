先走跑脚本。`task/` 里有对得上的就直接跑并报告；没有一份直接对应、但现有脚本能拼（只用这些脚本里已经验证过的逻辑），就在 `tmp/` 组合，试通了 `mv` 进 `task/` 再跑并报告。硬规则：本用户任务内跑 `tmp/` 且 stdout 为 `status: success` 或 `status: failure` 的次数合计最多 8，同一接口最多 3，先碰到哪条停哪条；`need-*` 等人「好了」后重跑同一条、只有 `error` 没有 `status`、以及 `node .../task/` 都不算。没有相关脚本、或现有脚本拼不成这次任务（含同一接口满 3 次还没 success）：立刻走录抓包，让用户在新窗口演示一遍——不要自己打开站点查看，不要写脚本探接口，不要猜请求。合计满 8 次还没 success：停，对人报告，不要再跑 `tmp/`，也不要开录。`record-start` 等人做完，`record-stop` 交出 `recordDir`。有了抓包再走写重放：对着 `timeline.jsonl` 和 request 在 `tmp/` 用 `yodo.run` + `pageForOrigin` + `evaluate` 写脚本（只重放抓到的，没抓到的不补），仍受上面 8 / 3 约束（含组合阶段已用掉的次数），试通了交给跑脚本那一套留下并报告；满 3 或满 8 仍无 success 则停并报告（检验 URL 由 agent 看 task 脚本现拼，脚本不 return `url`）。需要浏览器的命令自己连 Chrome；连不上就把 stdout 的 `guide` 原样念给用户，停，等「好了」再重跑刚才那条命令——不单独成一项，写在每条会连浏览器的 use case 里。
