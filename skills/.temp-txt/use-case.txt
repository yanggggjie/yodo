来源：sdk.ts / protocol.ts / bin/*.js / templates/task-common / record/write.ts；用户要求：没有相关任务脚本、或无法组合完成任务时，立刻开录让用户演示，不要自主探索。硬规则：本用户任务内跑 `tmp/` 且 stdout 为 `status: success` 或 `status: failure` 的次数合计最多 8，同一接口最多 3，先碰到哪条停哪条。
执行 SKILL 时 `.yodo` 已立好（立目录、Node、Chrome 安装在 `install.md`，不进本文件）。

一条 use case = 一个可单独做完的目标，不是步骤，也不是 holder / CDP 实现细节。

没有 CLI。对外是：`yodo` SDK、`src/bin/*.js` 薄脚本、`task/` `tmp/` 里的自执行脚本。需要浏览器的命令会自己连；连不上打印 `{ status, guide }` 后立刻返回，不轮询。

1. 跑已有 task
   目标：用户要做的事，`.yodo/task/*.js` 里已有对得上的已验证脚本。
   操作：读文件头 `@summary` 和 argv 说明；`node <home>/.yodo/task/<name>.js [参数]`。需要浏览器时命令自己连。stdout 是 `need-*` 就把 `guide` 原样念给用户，停，等「好了」再重跑。`success` 用 `result` / `resultFile` 对人讲；检验 URL 由 agent 看这份 task 脚本现拼（正确 path + query），脚本不要 return `url`。找不到对得上的文件：不要自己打开站点查看，不要写脚本试接口，不要猜 URL；去「录用户操作」。
   可观察结果：stdout 有 `status: success`（及 `result` 或 `resultFile`），或已把 `guide` 念出并在等「好了」；直接跑现成 task 得到 `failure` 则停、不改 `task/` 原文件。没有对得上的：已转入录用户操作，没有先探索站点。跑 `task/` 不计入下面的 8 次 / 3 次。

2. 组合现有 task
   目标：没有一份直接对应，但现有脚本能拼成这次要的——只用这些脚本里已经验证过的逻辑，不发明新接口。
   操作：在 `.yodo/tmp/` 写新文件（不改 `task/` 原文件），`import` `_common/yodo.js` 和现有逻辑，`node <home>/.yodo/tmp/<name>.js`。计入口径：stdout 为 `status: success` 或 `status: failure` 才算一次；`need-*` 等人「好了」后重跑同一条、只有 `error` 没有 `status`、以及随后的 `node .../task/` 都不算。同一接口最多 3 次，本用户任务内 `tmp/` 合计最多 8 次，先碰到哪条停哪条。`success` 后才 `mv` 进 `task/`，再跑那份 task 并报告。需要现有脚本里没有的接口、或同一接口满 3 次还没 `success`（合计未满 8）：立刻去「录用户操作」。合计满 8 次还没 `success`：停，对人报告，不要再跑 `tmp/`，不要开录。不要自己打开站点查看，不要写脚本探接口，不要猜请求。
   可观察结果：`tmp` 上出现过 `status: success`，`task/` 多了一份能再跑成功的文件，并对人讲了结果；或已转入录用户操作（拼不成 / 同一接口满 3 次）；或合计满 8 次后已停并报告。没有先自主探索。没出现过 `success` 不准进 `task/`。

3. 录用户操作
   目标：没有相关 task、或现有脚本拼不成这次任务时，立刻开录，让用户在新窗口演示一遍，拿到可读的抓包。不要先自己探索站点再决定要不要录。合计已满 8 次还没 `success` 时不要开录。
   操作：`node <home>/.yodo/src/bin/record-start.js [name]`。`recording` 时念 `guide`（请用户在新窗口做一遍），等「好了」，再 `record-stop.js`。只在新窗口做。不要这次了就 `record-abort.js`。正在录时不读 `record/.active/`。
   可观察结果：`status: stopped` 且有 `recordDir`（内含 `timeline.jsonl` 和 request 文件）；或 `aborted` / `idle`（没有可用抓包）。开录之前没有自己打开站点、没有写探接口脚本。

4. 对着抓包写出脚本
   目标：把抓到的请求变成可重复跑的自执行脚本。
   操作：读 `timeline.jsonl` 定接口，再打开对应 request JSON。在 `tmp/` 写脚本：`yodo.run` + `pageForOrigin` + `page.goto` + `page.evaluate` 在页内重放（只发网络请求，不操作 DOM）。闭包 return 业务数据，不要写 `url` 字段。计入口径与「组合现有 task」相同：`tmp/` 上 `success` / `failure` 算一次，同一接口最多 3，本用户任务合计最多 8（含组合阶段已用掉的），先碰到哪条停哪条。`success` 后 `mv` 进 `task/` 再跑并报告；检验 URL 由 agent 看脚本现拼。没抓到的请求不补、不猜。同一接口满 3 次或合计满 8 次仍无 `success`：停，对人报告，不要再改 `tmp/` 再跑。
   可观察结果：出现过 `status: success`，脚本已在 `task/`，并对人讲了结果；或满 3 / 满 8 后停，写清接口、原因、试了什么。没出现过 `success` 不准进 `task/`。
